# ハードウェアに関するメモ

このプロジェクトはハードウェアに依存しません — ブループリントはエンティティの種類だけを気にし、メーカーは問いません。このページでは、リファレンス構成を作って運用する中で実際に重要だった点をまとめています。買い物の判断材料にしてください。

## カメラ / AI検出

- Frigate が対応するカメラ（または同等の物体検出パイプライン）であれば何でも使えます。ペット対応機能で重要なのは GPU の生の演算性能ではなく、**ハードウェアによる動画デコード（NVDEC 相当）**です。安価で古い GPU でも、複数のカメラストリームを並行してデコードし、検出器を十分な速度で動かせます。
- ブラウザ再生やリモート視聴のためにストリームをトランスコードする場合（例えば go2rtc を使う場合。ブラウザ対応コーデックをネイティブでサポートしないカメラでよく必要になります）、これは検出とは**別のコスト**であり、ソフトウェア（CPU）エンコードだとすぐに重くなります。**ハードウェアエンコード（NVENC 相当）**対応の GPU を使えば、その負荷を CPU から外せます。安価な GPU はデコードには対応していてもエンコードには対応していないことが多いので、購入前に「GPUがあるかどうか」だけでなく両方のスペックを確認してください。
- ペットの検出にカスタム学習や独自モデルは不要です。「犬」「猫」といった種は、Frigate の検出モデルの多くが標準搭載する80クラスのCOCOラベルセットにすでに含まれています。カメラの追跡対象オブジェクトリストに種を追加するだけで済みます。

## 認証デバイス（指紋 / テンキー / NFC）

- Home Assistant 上で「どの人物が一致したか」を数値または文字列IDとして `sensor.*` に公開できるものであれば、何でもアーム/ディスアームのトリガーとして使えます。リファレンス実装では Zigbee/Tuya の指紋リーダーを使用しています。
- デバイスにアドレス指定可能なステータスLEDがある場合、HA の `light.*` エンティティに接続しておくと設置時やエラー時のフィードバックとして便利ですが、ここにあるどのブループリントも必須にはしていません。

## サイレン

- 標準的な12Vサイレンを駆動する単純なリレーやスマートスイッチで十分です — 専用の「スマートアラーム」ブランドのサイレン製品は不要です。ブループリントが呼び出すのは `switch.turn_on` / `switch.turn_off` だけです。

## 音声アナウンス

- `assist_satellite.*` エンティティであれば何でも使えます — ESPHome ベースの音声サテライト、Home Assistant 純正の音声ハードウェアなど。ブループリントは device ID の**リスト**にアナウンスするため、複数のサテライトを同時に対象にでき、うち一台がオフラインでも問題なく動作します。

## 外出先での確実な在宅検知

- 電話ベースの在宅検知（`person.*` / `device_tracker.*`）は、自宅のWi-Fiを離れた後も電話がHome Assistantインスタンスへのライブ接続を維持している場合にのみ正確さを保ちます。そうでない場合、電話がWi-Fiから外れた瞬間に在宅状態は「最後に分かっていた状態」で固まってしまい、`auto_arm_away.yaml` がひそかに機能しなくなります。
- これを解決するのが常時接続VPNです。難しいものである必要はありません — ネットワーク側は**WireGuardのクライアント/サーバーを内蔵**した一般消費者向けルーター（別途アドオン機器は不要）で十分です。電話側では、自動化アプリでサードパーティ製VPNアプリのオン/オフを切り替えるのではなく、OS標準の「常時接続VPN」設定を有効にしてください。多くの自動化アプリはVPNアプリを*起動*できるだけで、トンネルの開始/停止を確実に制御することはできません。

## 最低限必要なハードウェア

- ペット対応機能が欲しい場合のみ、ハードウェア動画デコード対応のGPUが1つ必要です — それ以外の場合はまったく不要です。
- 各入口ごとに1つの認証センサー（指紋 / テンキー / NFC）。
- 既存のドア/窓/動体センサー — アラーム専用のものは不要で、標準的なHAの `binary_sensor` エンティティがそのまま使えます。
- リレー駆動のサイレン。
- それ以外（音声アナウンス、外出時の自動アーム）はすべてオプションで、追加で組み込めます。
